# Holdouts

One folder per machine, named by the machine in the standard text format: for each state A to F, what it does on
reading a 0 and on reading a 1 (write, move, next state; `---` halts).

| machine | bbchallenge id | proofs |
|---|---|---|
| [`1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC`](1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC) | 36670 | Coq (kernel only, no axioms); Lean (kernel and `native_decide`) |
| [`1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB`](1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB) | 113677 | Coq (kernel only, no axioms); Lean (kernel only) |

Each folder has the same layout:

- `README.md`: what the machine does, why it never halts, what is proved where, and the commands to check it.
- `lean/`: the Lean proof. `lean/check.sh` compiles it with the shared library `../tools/lean`. Most files are
  generated by the scripts in `py/`, and say so in their first lines.
- `py/`: the scripts that found the structure and write the Lean files, and `proof_page.py`, which copies the
  hand-written proof walkthrough `proof_page.html` into `status.json`.
- `c/`: fast simulators used to find and test the structure (evidence, not proof).
- `status.json`: every result about the machine, each tagged by what it rests on. The two pages of the machine are
  built from it.

The Coq proofs of both machines are in [`../coq`](../coq).

Files here that are not about one machine:

- `build_pages.py` writes `../pages/` from the `status.json` files.
- `triage.json` holds the first look at each machine (10⁹ steps of `../tools/c/triage.c`), which the status pages
  cite.
