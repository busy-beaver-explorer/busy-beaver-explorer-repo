# Busy Beaver Explorer: two BB(6) holdouts that never halt

The [bbchallenge](https://bbchallenge.org) project is deciding, for every Turing machine with six states and two
symbols, whether it halts when started on a blank tape. A few hundred *holdouts* are still open. This repository
proves that two of them never halt, each one twice: once in Lean and once in Coq, on top of
[busycoq](https://github.com/meithecatte/busycoq).

| machine | bbchallenge id | Coq | Lean |
|---|---|---|---|
| `1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC` | 36670 | kernel only, no axioms | kernel, plus `native_decide` for the long runs |
| `1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB` | 113677 | kernel only, no axioms | kernel only (standard axioms) |

**Read the proofs on the site:** https://busy-beaver-explorer.github.io/busy-beaver-explorer-repo/
(built from [`pages/`](pages)). For each machine there is an explainer that runs the machine in your browser and walks
through the proof step by step, and a status page that lists every result by what it rests on.

## How the proofs go, in one paragraph each

**36670.** Each time the head comes back to the left end, the tape reads as a list of counts written in stretches
of `01`. Each round trip takes 3 from the first count, while the rest of the list cycles through one of four
periodic patterns. When the first count runs out, the second takes its place and a longer epoch begins. The proof
has 62 tape templates with the counts as variables. Every round trip and every way an epoch can end is checked as
a symbolic run. A potential on the counts shows that each epoch ends with enough room for those runs.

**113677.** The run alternates between long phases at the right end and phases of round trips. The proof has 15
phase forms and 27 rules between them, proved for all sizes. It follows those rules from the blank tape for 196
moves. A set of linear inequalities on the counts then holds, and every rule restores it.

Each machine's README ([36670](holdouts/1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC/README.md),
[113677](holdouts/1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB/README.md)) has the full story.

## Layout

| path | what is there |
|---|---|
| [`coq/`](coq) | the busycoq proofs of both machines, their symbolic runner (proved sound), the generators that write them, and `build.sh` |
| [`holdouts/M/`](holdouts) | one folder per machine: README, the Lean proof (`lean/`), the scripts that found the structure and write the Lean files (`py/`), C simulators (`c/`), and `status.json`, the source of its pages |
| [`tools/`](tools) | what is not about one machine: the Lean library `TM` (machine semantics, a verified list simulator), the Python package `bbtools` (parser, simulator, symbolic simulation), a C simulator, and the page builders |
| [`pages/`](pages) | the site, generated by `holdouts/build_pages.py` and published by `.github/workflows/pages.yml` |
| [`scripts/`](scripts) | `setup-lean.sh` installs Lean; `check_generated.sh` regenerates every generated file and fails if one changed |

## Check it yourself

```sh
# Coq (8.18; on Ubuntu 24.04: sudo apt-get install coq). Clones busycoq at a fixed commit. About 4 minutes.
sh coq/build.sh

# Lean 4.34.0, core only (no Lake). About 5 minutes for 36670 and 6 for 113677.
sudo bash scripts/setup-lean.sh && . /etc/profile.d/lean.sh
holdouts/1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC/lean/check.sh
holdouts/1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB/lean/check.sh

# Every generated file (Lean, Coq, the walkthroughs, the pages) is what its generator writes now. Python 3 only.
sh scripts/check_generated.sh
```

`.github/workflows/check.yml` runs all three on every pull request that touches them. In Coq, each proof ends with
`Print Assumptions nonhalt`, which prints *Closed under the global context*. In Lean, run
`#print axioms H36670.nonhalting` or `#print axioms H113677.nonhalting`.

## What to trust

Both statements are about the machine's real semantics: busycoq's `TM.v` in Coq, and `tools/lean/TM/Basic.lean`
in Lean. A machine table is generated from the machine's name. Everything between the semantics and the theorem is
checked by the proof assistant's kernel, with one exception: the Lean proof of 36670 trusts Lean's compiler for its
two `native_decide` checks. The Coq proof of the same machine does not. The certificates (tables, forms, numbers)
need no trust, since a wrong entry makes a check fail rather than pass. The C and Python programs found the
structure and give independent evidence, but no proof rests on them.

## Editing

Most files under `holdouts/M/lean/`, `coq/H*/` and `pages/` are generated. Edit the generator or the source
(`py/*.py`, `py/proof_page.html`, `status.json`, `coq/gen/`), rerun `sh scripts/check_generated.sh` to see what
changed, and commit the regenerated files with it.
